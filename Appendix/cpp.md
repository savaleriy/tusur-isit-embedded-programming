# Приложение. C++ для микроконтроллеров

Справочник по тем возможностям C++, которые применяются в курсе. Предполагается, что основы C вы уже знаете - если нет, начните с [приложения по языку C](c.md).

Практическое применение разбирается на [занятии 11](../Practice/11-cpp-oop/note.md).

## 1. Что такое C++ применительно к Arduino

Скетч Arduino компилируется компилятором **C++**, а не C. Это значит, что вам с самого первого занятия доступны перегрузка функций, ссылки, классы и `bool` как встроенный тип - просто до занятия 11 мы этим сознательно не пользовались.

Ядро Arduino само написано на C++: `Serial`, `String`, `LiquidCrystal`, `Servo` - это классы.

Компилятор для AVR - **avr-g++**. Он поддерживает современный стандарт языка, но часть возможностей отключена по умолчанию (исключения, RTTI), а часть непригодна из-за ограничений памяти.

## 2. Отличия от C, важные сразу

### Строгая типизация

```c
/* C: компилируется */
void *p = malloc(10);
char *s = p;
```

```cpp
// C++: ошибка, нужно явное преобразование
void *p = malloc(10);
char *s = (char *)p;
```

### bool - настоящий тип

```cpp
bool flag = true;
```

В C для этого нужен `<stdbool.h>`, а сам тип - синоним `int`. В C++ `bool` занимает 1 байт и имеет ровно два значения.

### Объявление переменных где угодно

```cpp
for (int i = 0; i < 10; i++) {   // i существует только внутри цикла
    int square = i * i;
}
```

Объявляйте переменную **в момент первого использования** и как можно ближе к нему: меньше шансов забыть инициализацию и проще читать.

### struct не требует ключевого слова

```c
/* C */
struct Point p;
typedef struct Point Point;
```

```cpp
// C++
Point p;                 // typedef не нужен
```

В C++ `struct` и `class` различаются **только** доступом по умолчанию: в `struct` он `public`, в `class` - `private`.

### Комментарии, const, inline

`//` работает и в современном C, а `const` в C++ создаёт настоящую константу времени компиляции (в C это "переменная, которую нельзя менять").

## 3. Ссылки

Ссылка - это второе имя существующего объекта.

```cpp
int value = 10;
int &ref = value;      // ref - другое имя для value
ref = 20;              // теперь value == 20
```

Отличия от указателя:

| | Указатель | Ссылка |
| --- | --- | --- |
| Может быть нулевым | Да | Нет |
| Можно переназначить | Да | Нет, привязывается один раз |
| Синтаксис доступа | `*p`, `p->field` | `ref`, `ref.field` |
| Обязательна инициализация | Нет | Да |

### Передача в функцию

```cpp
void byValue(int x)   { x = 100; }    // копия, оригинал не меняется
void byPointer(int *x){ *x = 100; }   // меняет оригинал
void byReference(int &x){ x = 100; }  // меняет оригинал, синтаксис проще
```

```cpp
int a = 1;
byValue(a);      // a == 1
byPointer(&a);   // a == 100
byReference(a);  // a == 100
```

### Константная ссылка

Для больших объектов передача по значению означает копирование. Константная ссылка избегает копии и при этом гарантирует, что функция не изменит аргумент:

```cpp
void print(const SensorData &data) {   // без копирования, без изменения
    Serial.println(data.temperature);
}
```

Правило: **встроенные типы (`int`, `float`, `uint8_t`) передавайте по значению, структуры и объекты - по константной ссылке**.

## 4. Классы

Подробное введение - в [занятии 11](../Practice/11-cpp-oop/note.md). Здесь - справочная сводка.

```cpp
class Counter {
public:
    Counter(int start = 0);            // конструктор
    ~Counter();                        // деструктор

    void increment();                  // метод
    int value() const;                 // константный метод

    static int instanceCount();        // статический метод

private:
    int _value;                        // поле
    static int _count;                 // статическое поле, общее для всех объектов
};
```

Определение вне класса:

```cpp
int Counter::_count = 0;               // статическое поле нужно определить один раз

Counter::Counter(int start) : _value(start) {   // список инициализации
    _count++;
}

Counter::~Counter() {
    _count--;
}

void Counter::increment() { _value++; }

int Counter::value() const { return _value; }

int Counter::instanceCount() { return _count; }   // вызывается как Counter::instanceCount()
```

### Список инициализации

```cpp
Counter::Counter(int start) : _value(start) { }    // инициализация
Counter::Counter(int start) { _value = start; }    // присваивание
```

Первый вариант предпочтителен всегда, а для константных полей и ссылок - единственно возможен:

```cpp
class Sensor {
public:
    Sensor(uint8_t pin) : _pin(pin) { }   // только так
private:
    const uint8_t _pin;
};
```

Поля инициализируются **в порядке объявления в классе**, а не в порядке записи в списке. Компилятор с `-Wall` предупредит о несовпадении.

### Указатель this

Внутри метода доступен указатель `this` на текущий объект:

```cpp
void Counter::setValue(int value) {
    this->_value = value;              // явно
    _value = value;                    // то же самое, короче
}
```

Явный `this` нужен редко: при совпадении имён параметра и поля, при возврате ссылки на себя для цепочек вызовов, при передаче адреса объекта в C-функцию.

### Деструктор

Вызывается при уничтожении объекта. Для глобальных объектов на микроконтроллере он практически не вызывается никогда (программа не завершается), поэтому деструкторы в embedded-коде встречаются редко.

## 5. Перегрузка

Несколько функций с одним именем, различающихся параметрами:

```cpp
void show(int value);
void show(float value);
void show(const char *text);
```

Компилятор выбирает подходящую по типам аргументов. Именно так устроен `Serial.print()`, принимающий что угодно.

Перегрузка **не различается по типу возвращаемого значения** - только по параметрам.

### Перегрузка операторов

```cpp
class Vector2 {
public:
    Vector2(int x, int y) : _x(x), _y(y) { }

    Vector2 operator+(const Vector2 &other) const {
        return Vector2(_x + other._x, _y + other._y);
    }

    bool operator==(const Vector2 &other) const {
        return _x == other._x && _y == other._y;
    }

private:
    int _x, _y;
};

Vector2 a(1, 2), b(3, 4);
Vector2 c = a + b;
```

Применяйте умеренно: операторы уместны для математических типов (координаты, цвет, время), но `matrix + 5` для светодиодной матрицы никому ничего не скажет.

## 6. enum class

```cpp
enum class Direction : uint8_t { None, Up, Down, Left, Right };

Direction d = Direction::Up;

if (d == Direction::Up) { }
// if (d == 1) { }              - ошибка компиляции
// int x = d;                   - ошибка компиляции
int x = static_cast<int>(d);    // явное преобразование, если действительно нужно
```

Преимущества перед обычным `enum`:

- значения не "вываливаются" в общее пространство имён - можно иметь `Color::Red` и `Led::Red` одновременно;
- нет неявного преобразования к числу, значит нельзя случайно сравнить с чем попало;
- можно задать базовый тип и зафиксировать размер.

Используйте `enum class` для всех состояний конечных автоматов.

## 7. Шаблоны

Код, параметризованный типом:

```cpp
template <typename T>
T maximum(T a, T b) {
    return (a > b) ? a : b;
}

int   x = maximum(3, 7);
float y = maximum(1.5f, 2.5f);
```

Компилятор порождает отдельную функцию для каждого использованного типа. **Во время выполнения шаблон не стоит ничего** - но каждая новая комбинация параметров добавляет копию кода во Flash.

### Шаблон класса с параметром-числом

```cpp
template <typename T, uint8_t SIZE>
class Buffer {
public:
    void push(T value) {
        if (_count < SIZE) _data[_count++] = value;
    }
    T operator[](uint8_t i) const { return _data[i]; }
    uint8_t size() const { return _count; }

private:
    T _data[SIZE];
    uint8_t _count = 0;
};

Buffer<uint16_t, 16> samples;
```

Размер известен на этапе компиляции, память выделяется статически - именно то, что нужно на микроконтроллере.

Важная деталь: **шаблоны определяются целиком в заголовочном файле**. Разделить на `.h` и `.cpp`, как обычный класс, не получится - компилятору нужен весь текст шаблона в момент использования.

## 8. Пространства имён

```cpp
namespace Config {
    constexpr uint8_t LED_PIN = 13;
    constexpr uint16_t PERIOD = 500;
}

digitalWrite(Config::LED_PIN, HIGH);
```

Помогают избежать конфликтов имён в проекте из многих модулей. В небольших программах обычно избыточны, но для группировки констант удобны.

Директива `using namespace std;` в embedded-коде не применяется: стандартной библиотеки на AVR фактически нет.

## 9. Ограничения на AVR

### Не используйте

| Возможность | Причина |
| --- | --- |
| `new` / `delete` | Фрагментация кучи в 2 КБ ОЗУ |
| `String` | Постоянные перевыделения памяти, зависания через часы работы |
| STL (`vector`, `map`, `string`) | Динамическая память, большой объём кода |
| Исключения | Отключены по умолчанию, дороги по Flash и стеку |
| RTTI (`dynamic_cast`, `typeid`) | Отключено по умолчанию |
| `std::function`, лямбды с захватом | Могут выделять память |

### Замена String

```cpp
// плохо
String message = "T=" + String(temp) + " H=" + String(hum);
Serial.println(message);

// хорошо
char message[32];
snprintf(message, sizeof(message), "T=%d H=%d", temp, hum);
Serial.println(message);
```

Для дробных чисел на AVR `snprintf` по умолчанию не поддерживает `%f`:

```cpp
char buf[10];
dtostrf(temperature, 5, 1, buf);      // значение, ширина, знаков после запятой, буфер
```

### Виртуальные функции

Работают, но стоят денег: указатель на таблицу виртуальных функций (2 байта в каждом объекте), сама таблица во Flash, косвенный вызов вместо прямого.

Применяйте, когда действительно нужен единый интерфейс для разных реализаций. Не применяйте "на будущее".

### Обработчики прерываний

Метод класса нельзя передать в `attachInterrupt()`: у него есть скрытый параметр `this`. Обходной приём - статический метод и указатель на экземпляр:

```cpp
class Encoder {
public:
    void begin() {
        _instance = this;
        attachInterrupt(digitalPinToInterrupt(_pin), isrTrampoline, CHANGE);
    }

private:
    static Encoder *_instance;
    static void isrTrampoline() { _instance->handleInterrupt(); }
    void handleInterrupt() { _count++; }

    uint8_t _pin;
    volatile long _count;
};

Encoder *Encoder::_instance = nullptr;
```

Ограничение очевидно: так работает только один экземпляр на прерывание.

## 10. Практические соглашения курса

1. Поля класса именуются с подчёркиванием: `_pin`, `_state`.
2. Методы, не меняющие объект, помечаются `const`.
3. Поля инициализируются в списке инициализации, а не в теле конструктора.
4. Инициализация оборудования - в `begin()`, а не в конструкторе.
5. Константы - `constexpr`, а не `#define`.
6. Состояния автоматов - `enum class`.
7. Объекты и структуры передаются по константной ссылке.
8. Циклы по массиву объектов - `for (auto &item : array)`, обязательно со ссылкой.
9. Никакого `String` и динамической памяти.
10. Заголовочные файлы защищены `#pragma once`.
