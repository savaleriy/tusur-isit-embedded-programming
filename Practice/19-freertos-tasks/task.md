# Занятие 19. Задачи

**Оборудование:** Arduino UNO, PlatformIO, светодиоды, кнопки, потенциометр, DHT-11 или другой медленный датчик, дисплей (по возможности).

> Проект собирается в PlatformIO с зависимостью `feilipu/FreeRTOS`.

---

## 19.1. Первые задачи

**Описание.** Запустите FreeRTOS и убедитесь, что задачи действительно независимы.

**Требования.**

1. Три задачи: два светодиода с разными периодами (100 мс и 750 мс) и вывод счётчика тиков в Serial раз в секунду.
2. Все задачи имеют одинаковый приоритет 1.
3. Результат создания каждой задачи **проверяется**; при ошибке выводится сообщение и программа останавливается.

---

## 19.2. Точность системного тика

**Описание.** Измерьте реальное разрешение планировщика на UNO.

**Требования.**

1. Задача переключает вывод и вызывает `vTaskDelay(pdMS_TO_TICKS(N))` для N = 5, 10, 15, 20, 50, 100.
2. Для каждого значения измерьте **фактический** период (по `millis()` за 100 циклов).
3. Постройте таблицу: заданное значение, расчётное число тиков, фактический период, погрешность.
4. Объясните, почему для малых N погрешность достигает сотен процентов.

**Вопрос.** Какой минимальный период мигания можно надёжно получить через `vTaskDelay()` на UNO? Как бы вы реализовали мигание с периодом 2 мс?

---

## 19.3. Приоритеты и вытеснение

**Описание.** Продемонстрируйте работу вытесняющего планировщика.

**Требования.**

1. Задача A с **низким** приоритетом непрерывно выводит в Serial символы, изображая долгую работу.
2. Задача B с **высоким** приоритетом раз в секунду мгновенно реагирует на нажатие кнопки, зажигая светодиод.
3. Продемонстрируйте, что реакция задачи B не зависит от загруженности задачи A; измерьте время реакции.
4. Поменяйте приоритеты местами и повторите измерение. Приведите обе цифры.

---

## 19.4. Одна функция - несколько задач

**Описание.** Используйте параметр задачи.

**Требования.**

1. Одна функция `TaskBlink` создаёт **три** задачи для трёх светодиодов с разными периодами.
2. Параметры передаются через структуру; структуры объявлены глобально или статически.

---

## 19.5. Бюджет памяти

**Описание.** Определите, сколько задач помещается на UNO.

**Требования.**

1. Возьмите программу из задачи 19.1 и добавьте вывод `uxTaskGetStackHighWaterMark()` для каждой задачи.
2. Подберите **минимальный** размер стека для каждой задачи, при котором программа устойчиво работает, оставив запас 40 байт.
3. Добавляйте задачи по одной, пока создание очередной не завершится ошибкой. Укажите предельное количество.
4. Постройте таблицу: количество задач, суммарный размер стеков, свободная куча, свободная SRAM.
5. Включите `configCHECK_FOR_STACK_OVERFLOW` и реализуйте обработчик; намеренно занизьте стек одной задачи и покажите срабатывание.

**Вопрос.** Задача выводит в Serial строку через `snprintf` в локальный буфер на 64 байта. На сколько нужно увеличить её стек и почему?

---

## 19.6. Периодические задачи

**Описание.** Сравните два способа выдержки периода.

**Требования.**

1. Две задачи с периодом 500 мс: одна использует `vTaskDelay()`, вторая - `xTaskDelayUntil()`.
2. В теле каждой задачи выполняется работа переменной длительности (например, случайная задержка 0-100 мс, имитирующая обработку).
3. Каждая задача считает свои срабатывания; через 2 минуты выведите оба счётчика и сравните с идеальным значением 240.
4. Приведите накопленную ошибку в секундах за час работы для каждого варианта.

---

## 19.7. Переписывание конечного автомата

**Описание.** Покажите главное преимущество ОСРВ на конкретном примере.

**Требования.**

1. Возьмите **свой** конечный автомат с занятия 7 или 15 (светофор, шлагбаум, полив) - алгоритм с несколькими последовательными стадиями и ожиданиями.
2. Перепишите его как задачу FreeRTOS **линейным кодом** с `vTaskDelay()` вместо состояний.
3. Продемонстрируйте оба варианта кода рядом и сравните: количество строк, читаемость, лёгкость внесения изменений.

**Вопрос.** Насколько выросло потребление памяти? Стоит ли выигрыш в читаемости этой цены для вашей задачи? Обоснуйте ответ цифрами.

---

## 19.8. Энергосбережение через Idle

**Описание.** Используйте задачу Idle по назначению.

**Требования.**

1. Реализуйте `vApplicationIdleHook()`, переводящий процессор в режим `SLEEP_MODE_IDLE`.
2. Убедитесь, что все задачи продолжают работать корректно.

**Вопрос.** Почему в этом режиме процессор просыпается вовремя и задачи не опаздывают? Какое прерывание его будит?
