# Занятие 18. Низкий уровень: регистры, чистый C и ассемблер

**Цель занятия:** написать программу для ATmega328P без фреймворка Arduino, научиться настраивать периферию напрямую через регистры и понимать, во что компилируется код.

**Что понадобится:** Arduino UNO, светодиоды, кнопка, потенциометр, PlatformIO.

---

## 1. Зачем спускаться на уровень регистров

Фреймворк Arduino - это слой абстракции. Он экономит время и делает код переносимым, но у него есть цена.

| Аспект | Arduino | Регистры |
| --- | --- | --- |
| `digitalWrite()` | около 50 тактов | 1-2 такта |
| Размер минимальной программы | ~450 байт | ~150 байт |
| Занятые ресурсы | Timer0 занят всегда | Ничего не занято |
| Доступ к возможностям МК | Только к части | Ко всем |
| Читаемость | Высокая | Требует документации |
| Переносимость | На все платы Arduino | Только на это семейство |

Практические причины изучать этот уровень:

1. **Скорость.** Динамическая индикация, программные протоколы, обработчики прерываний - там, где такты считаются.
2. **Доступ к возможностям**, которых нет в API: точная настройка АЦП, режимы сна, компаратор, watchdog, нестандартные режимы таймеров.
3. **Понимание.** Читая чужой код и документацию, вы постоянно будете встречать прямую работу с регистрами.
4. **Переход на другие платформы.** STM32, ESP32, любой промышленный микроконтроллер программируются именно так - через регистры или через HAL, который является тонкой обёрткой над ними.
5. **Отладка.** Когда библиотека ведёт себя странно, понять причину можно только заглянув в регистры.

Главный источник знаний здесь один - [документация на ATmega328P](https://docs.arduino.cc/resources/datasheets/ATmega328P-datasheet.pdf). Умение находить в ней нужный регистр и понимать таблицу битов - основной навык этого занятия.

## 2. Битовые операции

Работа с регистрами - это работа с отдельными битами.

| Операция | Запись |
| --- | --- |
| Установить бит `n` | `x \|= (1 << n)` | 
| Сбросить бит `n` | `x &= ~(1 << n)` | 
| Инвертировать бит `n` | `x ^= (1 << n)` | 
| Проверить бит `n` | `if (x & (1 << n))` | 
| Установить несколько | `x |= (1 << a) | (1 << b)` |
| Сбросить несколько | `x &= ~((1 << a) | (1 << b))` |

Почему `(1 << n)`: сдвиг единицы на `n` позиций влево даёт число, в котором установлен только бит номер `n`.

$$1 << 5 = 0b00100000 = 32$$

Разбор типичной строки:

```cpp
DDRB |= (1 << PB5);
```

- `PB5` - константа из заголовков avr-libc, равная 5 (номер бита в порту B);
- `(1 << PB5)` даёт `0b00100000`;
- `|=` устанавливает этот бит в `DDRB`, не затрагивая остальные.

Ошибка, которую делают все хотя бы раз:

```cpp
DDRB = (1 << PB5);       // присваивание вместо установки бита
```

Такая запись **обнуляет все остальные биты** порта. Если на них что-то было настроено - настройка потеряна.

### Полезные макросы

```cpp
#define setBit(reg, bit)     ((reg) |= (1 << (bit)))
#define clearBit(reg, bit)   ((reg) &= ~(1 << (bit)))
#define toggleBit(reg, bit)  ((reg) ^= (1 << (bit)))
#define readBit(reg, bit)    (((reg) >> (bit)) & 1)
```

В avr-libc есть готовые `_BV(bit)` - то же самое, что `(1 << bit)`.

## 3. Порты ввода-вывода

Три регистра на каждый порт (см. [занятие 3](../03-digital-io/note.md)):

| Регистр | Назначение |
| --- | --- |
| `DDRx` | Направление: `0` - вход, `1` - выход |
| `PORTx` | Выход: уровень. Вход: включение подтяжки |
| `PINx` | Чтение состояния вывода |

Соответствие выводов Arduino и портов:

| Порт | Выводы Arduino | Биты |
| --- | --- | --- |
| PORTB | D8-D13 | PB0-PB5 |
| PORTC | A0-A5 | PC0-PC5 |
| PORTD | D0-D7 | PD0-PD7 |

Встроенный светодиод D13 - это **PB5**.

### Мигание на чистом C

```c
#include <avr/io.h>

#define F_CPU 16000000UL
#include <util/delay.h>

int main(void)
{
    DDRB |= (1 << PB5);            // D13 на выход

    while (1) {
        PORTB |= (1 << PB5);       // включить
        _delay_ms(500);
        PORTB &= ~(1 << PB5);      // выключить
        _delay_ms(500);
    }
}
```

Здесь нет ни `setup()`, ни `loop()`, ни библиотек Arduino. Программа компилируется примерно в 150 байт против 900 у эквивалентного скетча.

Обратите внимание: `F_CPU` **обязательно** определяется до включения `<util/delay.h>`, потому что `_delay_ms()` вычисляет количество тактов на этапе компиляции. Неверная частота даст неверные задержки.

### Особенность регистра PINx

Запись единицы в бит `PINx` **инвертирует** соответствующий бит `PORTx`. Это аппаратная возможность AVR, позволяющая переключить вывод одной инструкцией:

```c
PINB = (1 << PB5);          // переключить D13
```

Эквивалент `PORTB ^= (1 << PB5)`, но выполняется за один такт вместо трёх (чтение, изменение, запись).

### Чтение кнопки

```c
DDRD &= ~(1 << PD2);        // D2 на вход
PORTD |= (1 << PD2);        // включить подтяжку

if (!(PIND & (1 << PD2))) {
    // кнопка нажата (подтяжка -> нажатие даёт 0)
}
```

## 4. Сборка без фреймворка Arduino

### PlatformIO

Достаточно убрать строку `framework`:

```ini
[env:uno_bare]
platform = atmelavr
board = uno
board_build.f_cpu = 16000000UL
upload_protocol = arduino
build_flags = -Wall -Wextra -Os
```

Файл `src/main.c` (или `.cpp`) должен содержать функцию `main()`. Сборка и загрузка - обычные `pio run` и `pio run -t upload`.

### Вручную через avr-gcc

Инструментарий устанавливается пакетом `avr-gcc`, `avr-libc`, `avrdude` (подробности для разных систем - в [этой инструкции](https://wellys.com/posts/avr_c_setup/)).

```bash
# компиляция
avr-gcc -mmcu=atmega328p -DF_CPU=16000000UL -Os -o main.elf main.c

# преобразование в HEX
avr-objcopy -O ihex -R .eeprom main.elf main.hex

# просмотр размера
avr-size --format=avr --mcu=atmega328p main.elf

# загрузка через загрузчик Arduino
avrdude -p atmega328p -c arduino -P /dev/ttyUSB0 -b 115200 -U flash:w:main.hex
```

Флаг `-Os` оптимизирует по размеру - именно он используется для микроконтроллеров.

Полезный приём - посмотреть, во что превратился ваш код:

```bash
avr-objdump -S main.elf > main.lst
```

В получившемся файле исходный текст на C перемежается с ассемблерными инструкциями. Это лучший способ понять, чего стоит та или иная конструкция языка.

## 5. Периферия через регистры

### АЦП

```c
void adc_init(void)
{
    ADMUX = (1 << REFS0);                     // опорное - AVcc (5 В)
    ADCSRA = (1 << ADEN)                      // включить АЦП
           | (1 << ADPS2) | (1 << ADPS1) | (1 << ADPS0);   // предделитель 128
}

uint16_t adc_read(uint8_t channel)
{
    ADMUX = (ADMUX & 0xF0) | (channel & 0x0F);  // выбрать канал, не трогая старшие биты
    ADCSRA |= (1 << ADSC);                      // запустить преобразование
    while (ADCSRA & (1 << ADSC));               // ждать завершения
    return ADC;                                 // 16-битный результат
}
```

Предделитель 128 даёт частоту АЦП $16000000 / 128 = 125$ кГц - в рекомендованном диапазоне 50-200 кГц. При более высокой частоте точность падает.

Обратите внимание на строку выбора канала: `ADMUX & 0xF0` сохраняет старшие биты (настройку опорного напряжения), а младшие заменяет номером канала. Простое присваивание сбросило бы опорное напряжение.

### UART

```c
#define BAUD 9600
#define UBRR_VALUE ((F_CPU / 16 / BAUD) - 1)

void uart_init(void)
{
    UBRR0H = (uint8_t)(UBRR_VALUE >> 8);
    UBRR0L = (uint8_t)UBRR_VALUE;
    UCSR0B = (1 << TXEN0) | (1 << RXEN0);              // включить приём и передачу
    UCSR0C = (1 << UCSZ01) | (1 << UCSZ00);            // 8 бит данных, 1 стоп-бит
}

void uart_send(uint8_t data)
{
    while (!(UCSR0A & (1 << UDRE0)));                  // ждать освобождения буфера
    UDR0 = data;
}

uint8_t uart_receive(void)
{
    while (!(UCSR0A & (1 << RXC0)));                   // ждать байт
    return UDR0;
}

void uart_print(const char *s)
{
    while (*s) uart_send(*s++);
}
```

Формула регистра скорости:

$$UBRR = \frac{f_{CPU}}{16 \cdot \text{baud}} - 1$$

Для 16 МГц и 9600 бод получается 103. Дробная часть отбрасывается, отсюда погрешность скорости - для 9600 она составляет 0,2 %, что укладывается в допустимые 2 %. А вот для 115200 бод погрешность достигает 3,5 %, и связь становится ненадёжной - именно поэтому на платах Arduino часто ставят кварц 16 МГц вместо более "круглого".

### Прерывания

```c
#include <avr/interrupt.h>

volatile uint16_t counter = 0;

ISR(INT0_vect)
{
    counter++;
}

int main(void)
{
    DDRD &= ~(1 << PD2);          // D2 на вход
    PORTD |= (1 << PD2);          // подтяжка

    EICRA |= (1 << ISC01);        // прерывание по спадающему фронту
    EIMSK |= (1 << INT0);         // разрешить INT0
    sei();                        // разрешить глобальные прерывания

    while (1) { }
}
```

Макрос `ISR()` из avr-libc создаёт функцию с правильным именем, сохранением регистров и инструкцией возврата `reti`.

### Таймер в режиме CTC

```c
void timer1_init(void)
{
    TCCR1A = 0;
    TCCR1B = (1 << WGM12)                       // режим CTC
           | (1 << CS12) | (1 << CS10);         // предделитель 1024
    OCR1A = 15624;                              // 1 Гц при 16 МГц
    TIMSK1 = (1 << OCIE1A);                     // разрешить прерывание
    sei();
}

ISR(TIMER1_COMPA_vect)
{
    PINB = (1 << PB5);                          // переключить D13 одной инструкцией
}
```

## 6. Ассемблер AVR

### Архитектура

AVR - 8-разрядное RISC-ядро с 32 регистрами общего назначения R0-R31. Большинство инструкций выполняется за один такт.

Особенности регистров:

- **R0-R15** - ограниченный набор операций (нельзя работать с непосредственными константами);
- **R16-R31** - полный набор операций;
- **R26:R27** = X, **R28:R29** = Y, **R30:R31** = Z - 16-битные указатели для косвенной адресации.

### Основные инструкции

| Инструкция | Действие |
| --- | --- |
| `LDI Rd, K` | Загрузить константу в регистр (только R16-R31) |
| `MOV Rd, Rr` | Скопировать регистр в регистр |
| `LDS Rd, addr` | Загрузить из памяти |
| `STS addr, Rr` | Сохранить в память |
| `IN Rd, port` | Прочитать регистр ввода-вывода |
| `OUT port, Rr` | Записать в регистр ввода-вывода |
| `ADD`, `SUB`, `AND`, `OR`, `EOR` | Арифметика и логика |
| `INC`, `DEC` | Инкремент, декремент |
| `SBI port, bit` | Установить бит в регистре ввода-вывода |
| `CBI port, bit` | Сбросить бит |
| `SBIS port, bit` | Пропустить следующую инструкцию, если бит установлен |
| `RJMP addr` | Относительный переход |
| `RCALL addr` | Вызов подпрограммы |
| `RET`, `RETI` | Возврат из подпрограммы, из прерывания |
| `NOP` | Ничего не делать один такт |

### Мигание на ассемблере

```asm
.include "m328Pdef.inc"

.equ LED = 5              ; PB5

.org 0x0000
    rjmp main

main:
    sbi  DDRB, LED        ; PB5 на выход

loop:
    sbi  PORTB, LED       ; включить
    rcall delay
    cbi  PORTB, LED       ; выключить
    rcall delay
    rjmp loop

delay:
    ldi  r18, 100
d1: ldi  r19, 200
d2: ldi  r20, 200
d3: dec  r20
    brne d3
    dec  r19
    brne d2
    dec  r18
    brne d1
    ret
```

Инструкции `SBI` и `CBI` устанавливают и сбрасывают бит в регистре ввода-вывода **за один такт** - это то, во что в идеале компилируется `PORTB |= (1 << PB5)`.

Три вложенных цикла в `delay` - классический способ отсчитать время без таймера. Точное количество тактов считается вручную: каждая итерация внутреннего цикла занимает 3 такта (`dec` + `brne`).

### Ассемблерные вставки в C

Полностью на ассемблере сегодня почти не пишут - обычно вставляют отдельные фрагменты в код на C:

```c
// точная задержка на 1 такт
__asm__ __volatile__ ("nop");

// запретить и разрешить прерывания
__asm__ __volatile__ ("cli");
__asm__ __volatile__ ("sei");

// с операндами: сложить два числа
uint8_t add(uint8_t a, uint8_t b) {
    uint8_t result;
    __asm__ __volatile__ (
        "add %0, %1"
        : "=r" (result)          // выход
        : "r" (b), "0" (a)       // входы
    );
    return result;
}
```

Модификатор `__volatile__` запрещает компилятору переставлять или удалять вставку при оптимизации.

Практическое применение вставок - точные задержки в единицы тактов при формировании протоколов и атомарные операции. Для всего остального компилятор напишет код лучше человека.

## 7. Сравнение подходов

Одна и та же задача - мигание светодиодом с периодом 1 с:

| Реализация | Flash | SRAM | Тактов на переключение |
| --- | --- | --- | --- |
| Arduino, `digitalWrite()` | ~920 байт | 9 байт | ~50 |
| Чистый C, `PORTB |= ...` | ~150 байт | 0 байт | 3 |
| Чистый C, `PINB = ...` | ~150 байт | 0 байт | 1 |
| Ассемблер, `SBI` | ~60 байт | 0 байт | 1 |

Разница в размере кажется огромной в процентах, но абсолютные цифры невелики: 900 байт из 32 КБ - это 3 %. 

**Оптимизировать нужно то, что действительно является узким местом**, а не всё подряд.

Разумная стратегия для курса и для практики:

- основная логика - на C++ с фреймворком Arduino, где важна читаемость;
- критичные по времени участки (обработчики прерываний, развёртка индикации, программные протоколы) - прямая работа с регистрами;
- ассемблер - только там, где нужен точный подсчёт тактов.

## 8. Отладка на низком уровне

Без `Serial.print()` отладка выглядит иначе.

**Светодиод как индикатор.** Самый простой метод: зажечь светодиод в интересующей точке программы.

**Свой UART.** Функция `uart_print()` из раздела 5 занимает около 60 байт и даёт полноценный вывод.

**Аппаратная отладка.** Инструмент [Bloom](https://bloom.oscillate.io/) в связке с `avr-gdb` и отладчиком (Atmel-ICE, USBasp с прошивкой debugWIRE) позволяет ставить точки останова, смотреть регистры и память в реальном времени. Настройка описана в [этой инструкции](https://wellys.com/posts/avr_c_gdb_bloomsetup/).

**Симулятор.** `simavr` и отладчик Wokwi позволяют пошагово выполнять программу без железа.

**Дизассемблер.** `avr-objdump -S` показывает, во что превратился ваш код. Незаменим, когда компилятор "оптимизировал" что-то не так, как вы ожидали.
