# Занятие 7. Задачи

**Оборудование:** Arduino UNO, светодиоды (не менее 4), кнопки (2 шт.), потенциометр, DHT-11 или фоторезистор, зуммер.

---

## 7.1. Три независимых ритма

**Описание.** Продемонстрируйте, что кооперативная многозадачность действительно работает.

**Требования.**

1. Три светодиода мигают с периодами 200, 750 и 1300 мс - числа выбраны некратными намеренно.
2. Кнопка мгновенно (в пределах 20 мс) включает четвёртый светодиод на всё время удержания.
3. Раз в 2 секунды в Serial выводится значение потенциометра.
4. В программе **нет ни одного вызова** `delay()`.
5. Каждая задача оформлена отдельной функцией с внутренними `static`-переменными.

**Проверка.** Измерьте худшее время итерации `loop()` способом из конспекта и приведите цифру в отчёте.

---

## 7.2. Накопление ошибки

**Описание.** Экспериментально покажите разницу между двумя способами сброса таймера.

**Требования.**

1. Реализуйте две задачи с периодом 100 мс: одна использует `ts = millis()`, другая `ts += 100`.
2. Каждая задача считает число своих срабатываний.
3. Добавьте в `loop()` искусственную помеху: раз в секунду выполняйте `delay(37)`.
4. Через 60 секунд выведите оба счётчика и сравните их с идеальным значением 600.

**Вопрос.** На сколько разошлись счётчики? Оцените ошибку в секундах за час работы для каждого варианта. В какой задаче вы бы выбрали каждый из вариантов?

---

## 7.3. Секундомер

**Описание.** Реализуйте секундомер с управлением одной кнопкой.

**Требования.**

1. Состояния: `STOPPED`, `RUNNING`, `PAUSED`. Реализовать через `enum` и конечный автомат.
2. Короткое нажатие: старт / пауза / продолжение. Длинное нажатие (более 1 с): сброс в ноль.
3. Время выводится в Serial в формате `MM:SS.mmm` каждые 100 мс.
4. Светодиод индицирует состояние: не горит - остановлен, горит - идёт отсчёт, мигает - пауза.
5. Дребезг кнопки подавлен, `delay()` не используется.

**Дополнительно (по желанию).** Добавьте функцию "круг": второе нажатие кнопки во время работы фиксирует промежуточное время и выводит его отдельной строкой, не останавливая отсчёт. Храните до 10 кругов.

---

## 7.4. Светофор с пешеходным вызовом на конечном автомате

**Описание.** Перепишите задачу 3.1 в виде явного конечного автомата.

**Требования.**

1. Все состояния перечислены в `enum`, переходы реализованы в `switch`.
2. **Нарисуйте диаграмму состояний** и приложите её к отчёту (допустима схема в текстовом виде или изображение).
3. Нажатие кнопки в любом состоянии корректно обрабатывается; поведение при нажатии во время цикла определено вами и описано в отчёте.
4. При каждой смене состояния в Serial выводится строка `t=<millis> <старое> -> <новое>`.
5. Одновременно с работой светофора программа мигает служебным светодиодом с периодом 250 мс - доказательство неблокирующей работы.

---

## 7.5. Планировщик задач

**Описание.** Реализуйте простейший диспетчер, который вызывает функции по расписанию.

**Требования.**

1. Опишите структуру задачи:

```cpp
struct Task {
    void (*handler)();          // указатель на функцию задачи
    unsigned long period;       // период вызова, мс
    unsigned long lastRun;      // когда вызывалась в прошлый раз
};
```

2. Создайте массив из не менее чем четырёх задач.
3. Функция `runScheduler()` перебирает массив и вызывает те задачи, которым пора выполниться.
4. `loop()` состоит из одного вызова `runScheduler()`.
5. Добавьте в структуру поле `enabled` и функции включения/выключения задачи по индексу; продемонстрируйте их работу по нажатию кнопки.
6. Добавьте подсчёт статистики: сколько раз выполнялась каждая задача и какова её максимальная длительность.
7. Реализуйте однократные задачи (выполнить один раз через $N$ мс и удалить из расписания).

---

## 7.6. Неблокирующий опрос медленного датчика

**Описание.** Встройте блокирующий датчик в неблокирующую программу.

**Требования.**

1. DHT-11 (или другой медленный датчик) опрашивается раз в 2 секунды.
2. Параллельно светодиод мигает с периодом 100 мс, а кнопка обрабатывается с реакцией не хуже 20 мс.
3. Измерьте, на сколько миллисекунд чтение датчика удерживает процессор, и покажите это в отчёте (например, по "спотыканию" мигающего светодиода или прямым замером `micros()`).
4. Опишите в отчёте, какими способами можно уменьшить влияние блокирующего вызова на систему.
5. Реализуйте "мягкую" деградацию: если датчик не отвечает три раза подряд, программа переходит в режим тревоги (быстрое мигание красным) и продолжает попытки с увеличенным интервалом.
