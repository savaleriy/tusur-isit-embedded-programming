# Занятие 16. UART и связь двух микроконтроллеров

**Цель занятия:** разобраться в асинхронной последовательной передаче, научиться проектировать простой протокол обмена и соединить две платы Arduino UNO в одну систему.

**Что понадобится:** две Arduino UNO, перемычки, резисторы, светодиоды, кнопки, джойстики, светодиодная матрица или дисплей.

---

## 1. UART

**UART** (Universal Asynchronous Receiver/Transmitter) - аппаратный модуль последовательной передачи данных. В отличие от I2C и SPI, он **асинхронный**: общего тактового сигнала нет, обе стороны заранее договариваются о скорости.

### Линии

| Линия | Назначение |
| --- | --- |
| **TX** | Передача данных от устройства |
| **RX** | Приём данных устройством |
| **GND** | Общая земля, обязательна |

Соединение всегда **перекрёстное**: TX одного устройства идёт на RX другого.

```tikz Перекрёстное соединение двух плат по UART
\begin{tikzpicture}[x=1cm,y=1cm]
  \node[mcu, minimum width=26mm, minimum height=30mm] (a) at (0,0)   {Arduino A};
  \node[mcu, minimum width=26mm, minimum height=30mm] (b) at (8.6,0) {Arduino B};

  \foreach \y/\la/\lb in {1.0/{TX (D1)}/{RX (D0)}, 0/{RX (D0)}/{TX (D1)},
                          -1.0/{GND}/{GND}} {
    \node[lab, anchor=west] at ([xshift=2mm] a.east |- 0,\y) {\la};
    \node[lab, anchor=east] at ([xshift=-2mm] b.west |- 0,\y) {\lb};

  \draw[flow, draw=sig] (a.east |- 0,1.0) ++(1.55,0) -- ++(4.0,0)
        node[lab, above, pos=0.5] {данные A $\to$ B};
  \draw[flow, draw=clk] (b.west |- 0,0) ++(-1.55,0) -- ++(-4.0,0)

```

Без общей земли обмен не заработает: логические уровни отсчитываются относительно земли, и без общей точки "ноль" одной платы может оказаться "единицей" для другой.

### Кадр данных

Поскольку тактового сигнала нет, приёмник должен сам понять, где начинается байт. Для этого каждый байт обрамляется служебными битами:

```tikz Кадр UART: передача байта 0x53 на скорости 9600 бод, 8N1
\begin{tikzpicture}[x=1.15cm,y=0.85cm]
  % уровни
  \draw[muted,dotted] (-0.6,0) -- (12.4,0) node[right,font=\scriptsize,muted] {0};
  \draw[muted,dotted] (-0.6,1.4) -- (12.4,1.4) node[right,font=\scriptsize,muted] {1};

  % линия покоя, старт-бит, данные 0x53 = 1100 1010 (младшим битом вперёд), стоп
  \draw[sig,very thick]
    (-0.6,1.4) -- (0,1.4)        % покой
    -- (0,0) -- (1,0)            % старт (0)
    -- (1,1.4) -- (2,1.4)        % D0 = 1
    -- (2,1.4) -- (3,1.4)        % D1 = 1
    -- (3,0) -- (4,0)            % D2 = 0
    -- (4,0) -- (5,0)            % D3 = 0
    -- (5,1.4) -- (6,1.4)        % D4 = 1
    -- (6,0) -- (7,0)            % D5 = 0
    -- (7,1.4) -- (8,1.4)        % D6 = 1
    -- (8,0) -- (9,0)            % D7 = 0
    -- (9,1.4) -- (10.4,1.4);    % стоп (1) и покой

  % границы битов
  \foreach \x in {0,1,...,10} { \draw[muted!50,very thin] (\x,-0.35) -- (\x,1.75); }

  % подписи битов
  \node[font=\scriptsize,warn] at (0.5,0.6) {СТАРТ};
  \foreach \x/\bit/\name in {1/1/D0, 2/1/D1, 3/0/D2, 4/0/D3,
                             5/1/D4, 6/0/D5, 7/1/D6, 8/0/D7} {
    \node[font=\scriptsize] at (\x+0.5,0.68) {\bit};
    \node[font=\scriptsize,muted,below] at (\x+0.5,-0.35) {\name};
  }
  \node[font=\scriptsize,ok] at (9.7,0.75) {СТОП};

  % длительность бита
  \draw[<->,acc] (1,2.1) -- (2,2.1)
        node[midway,above,font=\scriptsize,acc] {104 мкс};
  \draw[<->,muted] (0,-0.95) -- (10,-0.95)
        node[midway,below,font=\scriptsize,muted] {кадр 10 бит = 1,04 мс};

  \node[font=\scriptsize,muted,align=center] at (-0.6,2.1) {покой\\(1)};
\end{tikzpicture}
```

- **Старт-бит** - всегда 0. Переход из состояния покоя (1) в 0 сообщает приёмнику: начинается байт.
- **8 бит данных**, младшим битом вперёд.
- **Бит чётности** - необязателен, в Arduino по умолчанию не используется.
- **Стоп-бит** - всегда 1, возвращает линию в состояние покоя.

Итого на один байт данных приходится **10 бит** линии. Отсюда формула времени передачи:

$$t = \frac{N_{\text{байт}} \cdot 10}{\text{скорость}}$$

Для строки в 30 символов на скорости 9600 бод:

$$t = \frac{30 \cdot 10}{9600} = 0.031 \text{ с} = 31 \text{ мс}$$

Это существенное время: за 31 мс микроконтроллер выполняет около полумиллиона инструкций. Вывод в Serial - **не бесплатная** операция, и увлечение отладочной печатью заметно замедляет программу.

### Скорость передачи

Скорость измеряется в **бодах** - число символов линии в секунду. Для UART без модуляции это совпадает с битами в секунду.

Стандартные значения: 300, 1200, 2400, 4800, 9600, 19200, 38400, 57600, 115200.

Обе стороны обязаны использовать **одинаковую** скорость. При несовпадении приёмник неверно нарезает битовые интервалы и выдаёт мусор - тот самый набор случайных символов в мониторе порта.

Точность тактирования тоже важна. Допустимое расхождение частот приёмника и передатчика - около 2 %. Кварцевый резонатор на Arduino даёт погрешность 0,005 %, а внутренний RC-генератор - до 10 %, поэтому платы без кварца часто не могут работать по UART на высоких скоростях.

## 2. Serial в Arduino

Аппаратный UART микроконтроллера выведен на **D0 (RX)** и **D1 (TX)**, и эти же линии через микросхему CH340 подключены к USB. Отсюда два практических следствия:

1. **К D0 и D1 ничего нельзя подключать** во время работы с компьютером и во время прошивки.
2. **Монитор порта и внешнее устройство конфликтуют**: они делят одни и те же выводы.

### Основные методы

```cpp
Serial.begin(9600);              // инициализация
Serial.end();                    // освободить выводы D0, D1

Serial.available();              // сколько байт в приёмном буфере
Serial.read();                   // прочитать один байт (-1, если пусто)
Serial.peek();                   // посмотреть байт, не извлекая
Serial.readBytes(buf, len);      // прочитать блок
Serial.readStringUntil('\n');    // прочитать до разделителя

Serial.write(byte);              // отправить один байт
Serial.print(value);             // отправить в текстовом виде
Serial.println(value);           // то же плюс перевод строки
Serial.flush();                  // дождаться завершения передачи

Serial.setTimeout(ms);           // таймаут для read-функций
```

### Буфер приёма

Библиотека Serial принимает данные **по прерыванию** и складывает их в кольцевой буфер размером **64 байта**. Программа забирает их оттуда методом `read()`.

Это значит:

- байты не теряются, пока программа занята чем-то другим, - но только 64 штуки;
- если данные приходят быстрее, чем программа их забирает, буфер переполнится и **данные потеряются молча**, без сообщений об ошибке;
- на скорости 9600 бод буфер заполняется за $64 \cdot 10 / 9600 = 67$ мс. Итерация `loop()` длительностью 100 мс уже опасна.

Вывод: при обмене между устройствами читайте порт в каждой итерации `loop()`, а не раз в несколько циклов.

### Разница print и write

```cpp
Serial.write(65);        // отправит один байт со значением 65
Serial.print(65);        // отправит два байта: символы '6' и '5'
Serial.print('A');       // отправит один байт 65 (код символа 'A')
```

`print()` предназначен для человека - он переводит число в текст. `write()` передаёт байты как есть и применяется при обмене между устройствами.

Для двоичного протокола `print()` не годится: значение 1000 займёт 4 байта вместо 2, а получателю придётся разбирать текст.

### Аппаратная часть


Обе платы работают от 5 В, согласование уровней не требуется.

**Главное неудобство:** пока платы соединены по D0/D1, ни одну из них нельзя прошить и ни с одной нельзя работать через монитор порта. Порядок работы получается такой: отключить перемычки, прошить обе платы, соединить, наблюдать результат по светодиодам или дисплею.

### Решение: SoftwareSerial

Библиотека `SoftwareSerial` эмулирует UART программно на **любых** цифровых выводах. Аппаратный порт при этом остаётся свободным для связи с компьютером.

```cpp
#include <SoftwareSerial.h>

SoftwareSerial link(10, 11);      // RX, TX

void setup() {
    Serial.begin(9600);           // с компьютером
    link.begin(9600);             // с другой платой
}

void loop() {
    if (link.available()) {
        char c = link.read();
        Serial.print(F("Принято: "));      // отладка идёт в компьютер
        Serial.println(c);
    }
    if (Serial.available()) {
        link.write(Serial.read());          // что напечатали в мониторе - уходит на вторую плату
    }
}
```

Схема соединения: `D11 (TX) платы A` -> `D10 (RX) платы B`, `D10 платы A` <- `D11 платы B`, земли соединены.

Ограничения SoftwareSerial:

- **приём и передача не могут идти одновременно** (нет полного дуплекса);
- **приём работает только на одном программном порте** за раз;
- реализация основана на точных задержках и **запрещает прерывания** во время обмена, что нарушает `millis()`;
- надёжная скорость - до 19 200 бод, выше начинаются ошибки;
- нагружает процессор: он вручную отсчитывает битовые интервалы.

Для учебных задач этого достаточно, но в реальном проекте предпочтительнее аппаратный порт или плата с несколькими UART (Mega имеет четыре).

## 4. Проектирование протокола

Соединить провода - половина дела. Нужно договориться, **что** передаётся.

### Наивный подход и его проблемы

```cpp
// Передатчик
link.print(x);
link.print(y);

// Приёмник
int x = link.parseInt();
int y = link.parseInt();
```

Что здесь не так:

- **нет границ сообщения**: приёмник, включившийся в середине посылки, разберёт число неправильно и уже никогда не синхронизируется;
- **нет проверки целостности**: искажённый байт превратится в правдоподобное, но неверное значение;
- **нет типа сообщения**: расширить протокол нечем;
- `parseInt()` **блокирует** программу до таймаута, если данные не пришли.

### Текстовый протокол

Простой и отлаживаемый вариант: сообщения-строки с разделителем.

```
LED:1\n
POS:120,45\n
PING\n
PONG\n
```

Приём построчно, без блокировки:

```cpp
char buffer[32];
uint8_t bufferPos = 0;

void pollLink() {
    while (link.available()) {
        char c = link.read();

        if (c == '\n') {                     // конец сообщения
            buffer[bufferPos] = '\0';
            handleMessage(buffer);
            bufferPos = 0;
        } else if (bufferPos < sizeof(buffer) - 1) {
            buffer[bufferPos++] = c;
        } else {
            bufferPos = 0;                   // сообщение слишком длинное - сбрасываем
        }
    }
}

void handleMessage(const char *msg) {
    if (strcmp(msg, "PING") == 0) {
        link.println(F("PONG"));
    } else if (strncmp(msg, "LED:", 4) == 0) {
        digitalWrite(LED_BUILTIN, msg[4] == '1');
    } else if (strncmp(msg, "POS:", 4) == 0) {
        int x, y;
        if (sscanf(msg + 4, "%d,%d", &x, &y) == 2) {
            setPosition(x, y);
        }
    }
}
```

Обратите внимание: символ `\n` играет роль **границы сообщения**. Приёмник, подключившийся в середине посылки, отбросит неполный фрагмент и со следующего перевода строки войдёт в синхронизм.

Достоинства текстового протокола: его видно в мониторе порта, легко отлаживать, легко расширять. Недостаток - избыточность: число 1000 занимает 4 байта вместо 2.

### Двоичный протокол с кадром

Когда важна скорость и объём, применяют двоичный кадр:

```tikz Структура двоичного кадра: маркер, заголовок, данные, контрольная сумма

```

```cpp
const uint8_t START_BYTE = 0xAA;

enum class MsgType : uint8_t { Ping = 1, Pong = 2, Position = 3, Score = 4 };

void sendPacket(MsgType type, const uint8_t *payload, uint8_t len) {
    uint8_t crc = (uint8_t)type ^ len;
    link.write(START_BYTE);
    link.write((uint8_t)type);
    link.write(len);
    for (uint8_t i = 0; i < len; i++) {
        link.write(payload[i]);
        crc ^= payload[i];
    }
    link.write(crc);
}
```

Приём двоичного кадра - это **конечный автомат**, потому что байты приходят по одному:

```cpp
enum class RxState : uint8_t { WaitStart, WaitType, WaitLen, WaitData, WaitCrc };

RxState rxState = RxState::WaitStart;
MsgType rxType;
uint8_t rxLen, rxIndex, rxCrc;
uint8_t rxBuffer[16];

void pollLink() {
    while (link.available()) {
        uint8_t b = link.read();

        switch (rxState) {
            case RxState::WaitStart:
                if (b == START_BYTE) rxState = RxState::WaitType;
                break;

            case RxState::WaitType:
                rxType = (MsgType)b;
                rxCrc = b;
                rxState = RxState::WaitLen;
                break;

            case RxState::WaitLen:
                rxLen = b;
                rxCrc ^= b;
                rxIndex = 0;
                if (rxLen > sizeof(rxBuffer)) { rxState = RxState::WaitStart; break; }
                rxState = (rxLen == 0) ? RxState::WaitCrc : RxState::WaitData;
                break;

            case RxState::WaitData:
                rxBuffer[rxIndex++] = b;
                rxCrc ^= b;
                if (rxIndex >= rxLen) rxState = RxState::WaitCrc;
                break;

            case RxState::WaitCrc:
                if (b == rxCrc) handlePacket(rxType, rxBuffer, rxLen);
                rxState = RxState::WaitStart;      // в любом случае ждём новый кадр
                break;
        }
    }
}
```

Здесь конечный автомат из [занятия 7](../07-timing-multitasking/note.md) применён по прямому назначению: разбор потока, приходящего по частям.

### Контрольная сумма

Показанная выше сумма по исключающему ИЛИ (XOR) - самая простая. Она обнаруживает любую одиночную ошибку, но пропускает некоторые парные. Для учебных задач достаточно.

Более надёжный вариант - CRC-8:

```cpp
uint8_t crc8(const uint8_t *data, uint8_t len) {
    uint8_t crc = 0;
    while (len--) {
        uint8_t inbyte = *data++;
        for (uint8_t i = 8; i; i--) {
            uint8_t mix = (crc ^ inbyte) & 0x01;
            crc >>= 1;
            if (mix) crc ^= 0x8C;
            inbyte >>= 1;
        }
    }
    return crc;
}
```

### Подтверждения и таймауты

Если сообщение важно, отправитель должен убедиться, что оно дошло:

```cpp
unsigned long lastSend = 0;
bool waitingAck = false;
uint8_t retries = 0;

void sendReliable(MsgType type) {
    sendPacket(type, nullptr, 0);
    lastSend = millis();
    waitingAck = true;
    retries = 0;
}

void updateLink() {
    if (!waitingAck) return;
    if (millis() - lastSend < 200) return;      // таймаут ожидания подтверждения

    if (++retries > 3) {
        waitingAck = false;
        onLinkLost();                            // связь потеряна
        return;
    }
    sendPacket(lastType, nullptr, 0);            // повтор
    lastSend = millis();
}
```

Это уже элементы настоящего сетевого протокола: повторы, таймауты, обнаружение обрыва связи.

## 5. Связь двух плат по I2C

UART - не единственный способ. Две платы можно соединить по I2C, где одна будет ведущим, а вторая ведомым.

**Ведущий** (передаёт):

```cpp
#include <Wire.h>

void setup() {
    Wire.begin();                    // без адреса - режим ведущего
}

byte counter = 0;

void loop() {
    Wire.beginTransmission(8);       // адрес ведомого
    Wire.write("x is ");
    Wire.write(counter);
    Wire.endTransmission();
    counter++;
    delay(500);
}
```

**Ведомый** (принимает):

```cpp
#include <Wire.h>

void setup() {
    Wire.begin(8);                   // адрес ведомого
    Wire.onReceive(receiveEvent);    // обработчик, вызывается по прерыванию
    Serial.begin(9600);
}

void loop() {
    delay(100);
}

void receiveEvent(int howMany) {
    while (Wire.available() > 1) {
        char c = Wire.read();
        Serial.print(c);
    }
    int x = Wire.read();
    Serial.println(x);
}
```

Соединение: A4-A4, A5-A5, GND-GND. Подтягивающие резисторы 4,7 кОм на обеих линиях к 5 В.

### Что выбрать

| | UART | I2C |
| --- | --- | --- |
| Инициатор обмена | Любая сторона в любой момент | Только ведущий |
| Число устройств | 2 | До 112 |
| Линий | 2 + земля | 2 + земля |
| Свободны ли выводы для отладки | Нет (или SoftwareSerial) | Да |
| Сложность программы | Ниже | Выше, обработчик по прерыванию |
| Длина линии | До нескольких метров | Десятки сантиметров |

Для игры на две платы, где обе стороны должны отправлять данные когда угодно, UART удобнее: у I2C ведомый не может заговорить первым - его приходится опрашивать.

## 6. Архитектура системы из двух плат

Прежде чем писать код, ответьте на четыре вопроса.

**1. Кто за что отвечает?** Разделение бывает разным:

- *по устройствам*: плата A обслуживает джойстик и кнопки, плата B - матрицу и звук;
- *по ролям*: плата A - "сервер" с игровой логикой, плата B - "клиент" с органами управления;
- *симметрично*: обе платы делают одно и то же, обмениваясь состоянием.

**2. Кто инициирует обмен?** Варианты: обе стороны шлют когда захотят; одна опрашивает другую; обмен строго по расписанию.

**3. Что делать при потере связи?** Программа обязана это обнаруживать - по таймауту молчания - и переходить в безопасное состояние: остановить двигатель, погасить индикацию, показать ошибку.

**4. Как отлаживать?** Продумайте заранее. Варианты: SoftwareSerial для связи и аппаратный порт для отладки; светодиод-индикатор состояния связи; счётчики принятых и отброшенных пакетов.

### Индикация состояния связи

Простой и очень полезный приём:

```cpp
unsigned long lastReceived = 0;
const unsigned long LINK_TIMEOUT = 500;

bool isLinkAlive() { return millis() - lastReceived < LINK_TIMEOUT; }

void updateLinkLed() {
    digitalWrite(LED_LINK, isLinkAlive());
}
```

Светодиод горит - связь есть, погас - потеряна. Это экономит часы отладки: сразу видно, проблема в передаче или в логике.
